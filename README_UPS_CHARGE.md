## 기준 자료

- 사용자 제공 간헐충전·온도보상·펄스방전 이미지.
- `프로토콜 맵 v3/ABM 축전지 충방전기능_FlowChart추가_UEMS용_260819.pdf`의 3~4·6~7·9~10·12~13쪽.
- 최신 UPS std v3.2 시험용 XLSX의 Param·Alarm Flag 및 BMS System v1.3의 통신맵·Bit_List.

원본보다 최신 자료를 우선한다. 다음 차이를 반영했다.

1. 원본의 BBC 대기 109는 최신 맵에서 바이패스 절체다. **109를 BBC 대기에 연결하지 않는다.**
2. 온도보상은 다른 주 운전과 병행할 수 있다. 주기적·펄스 방전 준비/실행 중에는 적용 요청을 보류하고, 실제 BAT Mode 3·4일 때도 보류한다. 스케줄 대기 중에는 온도보상을 막지 않는다.
3. 실행 중인 다른 주 운전을 자동 취소하여 새 주 운전을 시작하지 않는다. 시작 전 BAT Mode가 부동충전이 아니면 충돌 상태로 대기한다.
4. 최신 Param 설명은 주기적 방전이 취소 전까지 실행된다고 명시한다. 따라서 설정한 방전 시간이 경과하면 취소 요청을 내고, 실제 부동충전 복귀를 확인한다. DSP가 먼저 자연 복귀한 경우도 처리한다.

## 흐름

### 간헐충전

정상 조건 → BBC 기동 요청 → 종료 전압/SOC 도달 → 추가 충전 시간 경과 → BBC 대기 요청 → 새 표본에서 대기모드 확인 → 재충전 시작 전압/SOC 이하 또는 재시작 기간 경과 → BBC 기동부터 반복.

Disable/취소 시 BBC 기동 → 부동충전 요청 → 새 표본의 부동충전 상태 확인 후 종료한다. 종료 기준을 넘은 뒤의 추가 충전 타이머는 원본 순서도처럼 단계 진입부터 연속으로 센다. SOC와 전압의 경계 비교는 순서도의 `>=`·`<=`를 따른다.

간헐충전은 원본의 UEMS 수행 방식으로 구성했다. UPS 자체 간헐충전 명령 118/119를 동시에 사용하지 않는다. 실제 BBC 대기 명령은 확인 전이므로 요청 의미만 정의했다.

### 주기적 방전

정상 조건 → 월·주차·요일·시간 대기 → 원본의 `배터리전압 <= 부동충전전압` 분기에서는 초기 충전 시간 대기 → BMS 준비 확인 → UPS 방전 시작 확인 → 새 표본의 주기적 방전 모드 확인 → 설정 시간 경과 시 취소 요청 → BMS 취소 확인 → 부동충전 요청·실제 모드 확인 → 종료 전압·마지막 시각 기록 → 다음 스케줄 대기.

스케줄은 월 선택 비트 0~11, 월내 1~4주차, 일요일 0~토요일 6, 시간 0~23이다. **1~7일을 1주차로 세는 방식은 이번 코드의 설계 정의이며, 원본이 주차 계산법까지 확정한 것은 아니다.** 같은 날짜에는 한 번만 시작하며, 과거 날짜로 시계가 돌아가도 재실행하지 않는다. 실행 시간 전체에서 조건을 확인하며 지난 시간의 미실행 작업을 소급 실행하지 않는다.

첫 정상 완료 결과를 기준 결과로 보관하고, 이후 결과는 시작/종료 전압과 마지막 시각으로 갱신한다. 기준 초기화는 Idle/스케줄 대기 중에만 받는다. **운전 상태·스케줄 실행일·결과는 현재 메모리 값이며 영구 저장은 미연결이다.**

### 펄스방전

정상 조건 → BMS 준비 확인 → UPS 펄스 시작 확인 → 새 표본의 펄스모드 확인 → DSP가 설정된 충전/방전 시간·전류·횟수로 수행 → 부동충전 복귀 관측 → BMS 취소 확인 → 부동충전 요청·실제 모드 확인 → 완료.

PLC에서 충전/방전 펄스를 직접 발생시키지 않는다. 시작 직후 아직 부동충전인 상태를 완료로 오인하지 않도록 실제 펄스모드 진입을 먼저 확인한다. Enable이 계속 TRUE여도 완료 직후 재시작하지 않는다. 중간 취소 시 UPS 취소 → BMS 취소 → 부동충전 확인 순서로 종료한다.

### 온도보상

`목표 전압(V) = (25℃ 기준 셀 전압(V) + 기울기(mV/℃) × 0.001 × (배터리실 온도−25)) × 직렬 셀 수`

UPS 온도6을 사용한다. 설정한 온도·전압 범위 안에서만 적용을 요청한다. 설정 주기마다 다시 계산하며, Disable 시 기준 부동충전 전압으로 복귀를 요청한다. 적용 확인 뒤에만 적용 전압·마지막 시각을 갱신한다.

전압·전류·SOC·셀 수 등의 기본값은 0이며 그대로는 실행 조건을 통과하지 못한다. 문서의 납축 240셀·2.22V 예제를 실제 LiB 설정으로 넣지 않았다.

## 요청 확인과 보호

- 요청 번호가 일치하는 `bConfirmed=TRUE` 응답만 완료로 받는다. 이 응답은 **대기열 접수나 Modbus 쓰기 응답만을 뜻하지 않는다.** 필요한 설정·동작이 확인된 뒤 외부 담당 모듈이 제공해야 한다.
- 요청 확인과 운전 모드 진입에 각각 제한 시간이 있다. 취소로 단계가 바뀌면 이전 요청 확인을 다음 요청 완료로 재사용하지 않는다.
- 시작한 운전의 설정은 `q_stActiveSet`에 고정한다. 진행 중 외부 설정이 바뀌어도 같은 운전의 조건을 중간에 바꾸지 않는다.
- 현재는 UPS/BMS 유효 데이터, Rect/BBC Normal, 비상정지·BMS 중고장/고장·잠금 없음 등을 요구한다. **BMS Minor에서도 충방전 시퀀스를 막는 것은 보수적으로 추가한 잠정 조건**이다. 최신 맵은 Minor에서 충전정지/방전가능으로 구분하므로, 현장 운영 정책 확정 때 더 세분해야 한다.
- 통신/보호 이상이나 시간 초과 시 요청을 중단하고 Fault와 복구 필요 여부를 표시한다. 고장 대응·ESD 안전차단 시퀀스를 이 로직이 대신 수행하는 것은 아니다. Fault 리셋은 Enable을 끈 상태에서만 받는다.
